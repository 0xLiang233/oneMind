# 桌面稳定性与维护约定

## 结论与证据边界

这次处理的是悬浮窗焦点切换和长时间小程序浏览相关的高风险路径，不是更换桌面壳，也没有调整工作区文件格式。历史日志没有提供卡死现场的线程栈，所以不能把每一次历史卡死都归结为同一个原因，更不能用短时测试保证所有长时间运行场景。

代码审查确认的风险及对应处理：

| 风险 | 处理 |
| --- | --- |
| 同步 IPC 路径创建 WebView/窗口；WebView 回调里直接再导航，可能阻塞或重入原生消息循环 | 窗口和小程序命令改为异步入口，在串行后台执行器中执行原生操作；弹窗回调先返回，再调度导航。安装的 Tauri 2.11.3 `WebviewWindowBuilder::new` 文档也明确提示 Windows 同步命令创建窗口的死锁风险 |
| 悬浮窗跨线程/进程 `AttachThreadInput`、操作 Chromium 私有子 HWND、失焦后的延迟回抢 | 删除输入队列绑定和私有窗口枚举；只通过受支持的运行时 API 主动激活；generation 淘汰过期任务；失焦延迟后检查前台窗口，不依据鼠标位置抢焦点 |
| 焦点恢复本身重复触发 `Focused` 回调 | 主动激活与 DOM 输入焦点分开；焦点通知/延迟重试不能再次设置原生焦点；前端延迟任务不聚焦后台文档 |
| 随记保存失败后输入框一直禁用；上一次保存的延迟回调关闭新打开的悬浮窗 | 保存异常保留草稿并恢复编辑；提交同步去重；按请求代次隔离完成反馈和延迟隐藏，不取消已提交的磁盘写入 |
| 同步目录遍历、JSON 读改写、日志磁盘操作与 UI 争用 | 工作区 I/O 统一后台串行执行；日志有界队列、独立写线程和轮转；系统应用启动在后台执行 |
| 小程序进程退出没有可恢复提示，旧实例的异步回调可能影响新实例 | 监听 WebView2 进程失败，按实例编号过滤旧事件；隐藏异常网页并显示重试，不自动重载；前端等待有超时反馈，但不提前放开原生操作顺序 |
| 单文件混合窗口、存储、日志、网页生命周期 | 分离相关模块和前端 hook，并加入针对顺序、取消、并发写入和焦点边界的回归测试 |

注意：WebView2 的 `ProcessFailed` 不等于每次网页 JavaScript 忙碌都会立刻报告“无响应”。短暂繁忙不能直接视为崩溃。这里不增加周期性强制刷新或杀进程，以免丢失用户未提交的网页内容。

## 模块边界

原生目录：`desktop/tauri/src-tauri/src/`。

- `runtime.rs`：`SerialExecutor`、阻塞工作调度、慢操作诊断。存储、悬浮窗、小程序各有自己的执行通道；它们不共用一个全局原生锁。
- `float_note.rs`：创建/显示/隐藏/尺寸/快捷键/失焦生命周期。`activate_input` 仅用于主动激活；`focus_input` 只更新 DOM，不重新设置原生焦点。
- `float_note_focus.rs`：Windows 前台窗口查询。禁止恢复跨进程输入队列绑定。
- `miniapp.rs`：子 WebView 生命周期、实例编号、边界、原有认证/外部导航策略。
- `miniapp_health.rs`：Windows WebView2 进程失败适配；其他平台不伪造健康事件。
- `storage_commands.rs`：稳定 IPC 名称与参数的异步门面。`lib.rs` 中原有同步存储实现保持原有语义，继续供门面和测试调用；后续可按业务逐步拆分，避免一次性重写存储。
- `diagnostics.rs`：非阻塞日志入口、有界写入和轮转。
- `watchdog.rs`：主消息循环心跳，只记录故障与恢复，不杀进程、不自动重启。
- `lib.rs`：装配、保留的业务实现和应用入口。仍不是完全拆分后的理想结构；后续业务提取应按职责进行，不要把新增桌面生命周期逻辑堆回这里。

前端目录：`renderer/src/`。

- `miniapps/nativeViewQueue.ts`：原生操作实际完成顺序，以及调用者等待期限。
- `miniapps/useNativeMiniappView.ts`：当前路由实例、清理、尺寸观察、覆盖层显示/隐藏、进程失败提示。
- `views/SourcesPage.tsx`：目录和页面交互，不再内嵌完整原生生命周期。
- `platform/tauriBridge.ts`、`types/global.d.ts`：`window.oneMind` 兼容契约；`miniappView.onFailed` 是可选能力，不要求 Electron 同步实现。

## 必须保持的线程与生命周期规则

1. **原生回调先返回。** 不在 WebView2/窗口回调或同步 IPC 中创建、关闭、导航 WebView；调度到后台执行器。
2. **`async` 不等于不会阻塞。** 文件遍历、磁盘写入和可能等待 UI 的原生 API 仍须进入阻塞线程池；异步延时使用异步计时器。
3. **短锁只保护内存。** 不持有 `std::sync::Mutex` 调用需要 UI 线程处理的原生 API；否则 UI 回调再次获取锁可能相互等待。
4. **调用者超时/取消不是工作取消。** 前端默认 15 秒反馈超时，但仍让迟到的 show 先完成，再执行 cleanup/下一次 show。后台串行锁的所有权随实际工作保留，不能随调用者取消而释放。
5. **迟到事件检查身份。** 悬浮窗延迟任务检查 generation，小程序回调检查实例编号；旧任务不能操作同名新窗口。
6. **隐藏不等于销毁。** 打开菜单/覆盖层只 hide/show 同一小程序，不 reload/close；保留网页草稿、历史和登录状态。路由卸载沿用原有 close 行为。
7. **焦点事件必须幂等。** `Focused(true)` 内不可调用 `activate_input`/原生 `set_focus`；用户切到其他应用后不可用延迟回调抢回输入。
8. **远程内容不获得本地权限。** 保持原有远程页面隔离和窄桥接面，不向网页暴露 `window.oneMind` 或工作区文件访问能力。
9. **不改变持久化位置。** 小程序 label 编码可以改进，但 `miniapp-profiles` 下按 partition 生成的目录名不得随意改变，否则会表现为登录丢失。

## 日志与故障定位

Windows 默认位置（目录由 Tauri app-data API 解析）：

- `%APPDATA%\io.github.0xliang233.onemind\diagnostics\shell-log.jsonl`
- `%TEMP%\onemind-tauri.log`，用于启动早期/后备日志。

每个日志最多约 2 MiB，保留 3 个备份（`.1` / `.2` / `.3`）；单字段最多 8192 UTF-8 字节。日志队列最多 512 项，满时丢弃诊断而不阻塞 UI，之后记录 `diagnostic_queue_full`。正常退出最多等待 2 秒排空队列，不为日志无限等待。

关键事件：

| 事件 | 含义 |
| --- | --- |
| `ui_unresponsive` | 主消息循环超过 10 秒未响应已发送的心跳；每 5 秒检查，只有一个未完成心跳，不能据此推断具体卡住的调用 |
| `ui_responsive_again` | 同一心跳恢复，包含等待时长 |
| `slow_native_operation` | 实际后台操作执行超过 2 秒（不含进入串行通道前的排队时间） |
| `miniapp_process_failed` | 具体小程序实例异常；区分 `crashed` / `unresponsive`，可用时记录 WebView2 `kind`、`process_reason`、十进制/十六进制 `exit_code`（例如 `terminated`、`out_of_memory`） |
| `miniapp_renderer_operation_failed` | 包括前端等待超时；不代表已取消底层 IPC |
| `miniapp_health_install_failed` | 当前环境未成功安装 WebView2 健康监听，需要结合环境调查 |
| `diagnostic_queue_full` | 诊断高峰丢弃计数，不等同于业务数据丢失 |

开发构建默认带详细诊断。发布构建默认不写高频 `debug` / `renderer-debug`；排查时可临时设置 `ONEMIND_TAURI_DEBUG=1`。日志可能包含路径和导航地址，分享前应检查敏感信息。

再次遇到卡死时，保留上述两处日志及时间点、正在使用的小程序、是否切出悬浮窗。如果主循环心跳异常仍不足以定位，需要在卡住时采集线程栈/进程转储；不要仅凭“运行很久”判断是内存泄漏。

## 自动检查

在仓库根目录执行：

```powershell
pnpm --dir renderer test
pnpm --dir renderer lint
cargo test --manifest-path desktop/tauri/src-tauri/Cargo.toml --lib
pnpm build:tauri
```

前端测试使用 Node 的 `--experimental-strip-types`（本次使用 Node 22）；涵盖队列超时后的真实顺序、异常后恢复、焦点结构约束、原有窗口背景约束。原生测试涵盖取消调用者后通道仍被实际工作占用、32 个并发串行操作、64 个并发随记写入无丢失/无重复 ID、日志边界和轮转、小程序标签/导航/边界，以及原有附件与同步测试。

桥接面改动另跑 `pnpm build:desktop` 验证兼容编译即可，不因此启动或管理 Electron。实际桌面行为必须在重建并重启后的 Tauri 中验证，浏览器预览不能替代。

### 本地构建与发布签名

标准 Tauri 构建需要更新器签名私钥。没有私钥时，可能已编译并生成安装包，但在更新器签名阶段退出失败；不能报告为标准发布构建成功。仅用于本地验证时可以使用临时配置：

```powershell
$config = Join-Path $env:TEMP 'onemind-local-unsigned.json'
'{"bundle":{"createUpdaterArtifacts":false}}' | Set-Content -LiteralPath $config -Encoding ascii
pnpm build:tauri --config $config
```

不要修改仓库正式签名配置，不要用这个本地包替代正式签名发布产物。

## 桌面回归清单

在临时工作区、本地测试网页中执行破坏性故障测试，不向用户真实笔记或已登录网页注入脚本。

- 快捷键初次打开、重复打开/关闭，立即输入中文/多行内容，保存并在主窗口确认。
- 在临时工作区模拟一次随记写入失败：内容保留、错误可见、输入框恢复；重试成功。验证 Ctrl+Enter 保存后不关闭、Enter 保存后关闭、同一轮重复 Enter 不重复写入，以及旧保存迟到不清空/隐藏重新打开的草稿。
- 切换到主窗口/其他应用，悬浮窗应隐藏；快速切走再打开，旧的延迟任务不应关闭新一轮窗口，也不应抢焦点。
- 多显示器/不同 DPI、尺寸变化、最大高度、主窗口最小化后从悬浮窗打开路由。
- 菜单覆盖层反复开关，网页实例和未提交草稿不变；刷新仅在用户明确操作时发生。
- 小程序与随记/其他路由快速往返，子 WebView 数量不累积。
- 仅终止**已验证属于本地测试小程序的 renderer 进程**：主界面和本地读写继续可用，出现重试；明确重试后恢复，并保留 profile 中的持久化标记。不得批量结束 WebView2 进程。
- 让本地网页执行有上限的忙循环，检查主界面和 native IPC 可用。单独验证 WebView2 真正发出 `unresponsive` 事件的场景，不能把所有忙循环都当作此事件的验证。
- 认证跳转、同源弹窗、外部链接、历史后退/刷新等按原有产品行为检查；真实第三方登录需要受控账号人工回归。
- 长时间使用后观察句柄/内存和诊断；短时通过不等价于多小时浸泡或所有第三方网页通过。

调试器本身可能干扰 WebView 创建：避免自动 attach 后暂停新目标，也不要强制所有 WebView2 使用同一用户目录。测试结束关闭远程调试端口、恢复正常工作区，重启不含测试参数的 Tauri。

## 本轮验证记录

验证对象为 Windows 上的实际 Tauri 窗口，不是浏览器替代预览。破坏性测试只使用临时工作区和 `127.0.0.1` 本地网页；通过调试协议检查 DOM 和桥接调用，没有继续进行系统鼠标/键盘自动化。测试结束关闭调试实例和本地网页服务，再以正常参数启动 `pnpm dev:tauri`。

### 实际运行回归

- **悬浮窗：** 12 轮尺寸变化、切至主窗口、失焦后快速重新打开均通过；旧的延迟失焦任务不隐藏新一轮窗口。最新发布构建首次打开约 188 ms，焦点落在文本框；焦点通知不再递归设置原生焦点。
- **随记保存：** 开发构建和最新发布构建均验证了失败后保留草稿并恢复编辑、Ctrl+Enter 保存后保持打开、Enter 保存后关闭、同步重复 Enter 只写入一次，以及旧保存完成不清空或隐藏新打开的草稿。测试随记均位于临时工作区，并已清理。
- **网页覆盖层：** 开发构建 30 轮、最新发布构建另 10 轮；均只隐藏/恢复原有 WebView，未调用 reload/close，网页实例和未提交草稿保持不变。
- **网页生命周期：** 两轮各 20 次路由销毁/重建；小程序路由始终只有一个测试子 WebView，离开后为零；唯一的 localStorage 标记跨重建保留。同源 `window.open` 在既有子视图内导航正常。
- **实际子进程退出：** 仅终止经进程名、命令行、专属测试 profile 核验的本地测试 renderer。主窗口仍可操作，出现明确重试入口，不自动重载。最新发布构建本地随记增/查/删耗时 9 ms；明确重试后网页恢复，持久化标记仍在。新诊断实际记录了 `kind`、`process_reason`、`exit_code` 与 `exit_hex`。
- **网页繁忙：** 本地网页执行有上限的 60 秒 JavaScript 忙循环时，主页面探测约 0–2 ms，随后本地存储调用可用。此环境未产生 WebView2 `unresponsive` 通知，所以这项事件的真实触发与恢复**尚未完成运行时验证**。
- **长时间观察：** 生命周期压力后 2 分钟主动观察期间，页面实例、草稿与持久化标记均保留，最大 native 探测约 11 ms。另一次约 7 小时驻留中，测试网页约第 43 分钟发生子进程退出；之后检查主程序仍可响应，本地随记增/查/删约 16 ms，单独重试成功。**这不是网页连续运行 7 小时通过**。当时旧日志缺少退出码，不能认定该次退出是内存泄漏或本轮代码引起；因此补充了退出详情诊断。

尚需真实使用覆盖的场景：真实第三方账号登录及认证弹窗、中文输入法的系统级交互、多显示器/不同 DPI、睡眠唤醒，以及不附加调试器的更长时间运行。本轮保持原有功能和存储契约，并完成上述回归，但不把有限测试表述为所有环境绝不会再次卡死。
